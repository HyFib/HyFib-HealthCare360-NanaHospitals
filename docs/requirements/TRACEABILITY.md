# Requirements traceability (release 1)

Every requirement in [SRS.md](SRS.md), with the code that builds it, the tests that prove it, and a verdict:

* **Done**: built, and automated tests prove it. For a requirement about the project itself (style gates, decision
  records), the gate or the record is the evidence.
* **Partial**: built, but a part is missing or a rule is not proved by a test. *Gap* says which.
* **Missing**: not built.
* **Blocked**: cannot be finished from the code alone. *Who must act* names the outside party; *Gap* says what is built
  so far.

A *Who must act* entry on a **Done** row names what the hospital must provide before using it (an account, a licence,
a key); the code and its tests are complete.

The rows follow the SRS: one per requirement ID, or per range (`FO-01..06`) where the SRS describes a module in one
row. The verdicts come from a review of the code and tests in October 2026 (from commit `fd3f4b7d`, with the changes
that added this file). They describe evidence, not a certification: a **Done** row means the cited tests pass and
cover the requirement's rules as written, not that the hospital has accepted the module.

The architecture tests (`TraceabilityTests`) fail when an SRS requirement has no row here, a row has a verdict other
than these four, a non-Done row says no gap, a Blocked row names no one, or a link points to a file that does not
exist. Keep this file current in the same change as the code.
